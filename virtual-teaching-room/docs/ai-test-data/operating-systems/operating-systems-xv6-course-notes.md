# 操作系统（xv6 RISC-V 测试课程）

## 第1章 操作系统接口

操作系统位于应用程序和硬件之间，负责管理硬件资源，并向应用程序提供稳定、受保护的服务接口。它可以让多个程序共享处理器、内存和设备，也可以为程序之间的受控通信提供机制。

在 xv6 中，内核是一个具有更高权限的特殊程序。普通程序运行在用户空间，需要操作系统服务时，通过系统调用进入内核。进程通常包含用户空间中的指令、数据和栈，也包含由内核维护的进程状态。

常见系统调用包括：`fork` 创建进程，`exec` 使用可执行文件替换当前进程的程序内容，`exit` 结束进程，`wait` 等待子进程结束，`open` 打开文件，`read` 和 `write` 读写数据，`close` 关闭文件描述符，`pipe` 创建进程间通信管道。

## 第2章 操作系统组织

操作系统需要把物理资源抽象成应用程序可以使用的接口。xv6 使用内核和用户程序分离的结构：用户程序不能直接执行所有特权操作，内核负责检查请求并管理共享资源。

处理器通常区分用户态和管理内核所需的特权态。用户程序通过系统调用请求服务，硬件和内核共同完成权限切换。权限分离的目标是限制错误或恶意的用户程序，避免它直接破坏其他进程或内核数据。

内核组织方式会影响可靠性和安全性。xv6 将进程管理、内存管理、陷阱处理、设备驱动、文件系统等部分组合为一个教学内核，同时保持清晰的接口，方便学习者理解各模块如何协作。

## 第3章 页表

页表把进程使用的虚拟地址映射到物理地址。虚拟地址空间让每个进程可以拥有相对独立的地址视图，内核通过页表项中的权限位控制页面是否可读、可写、可执行，以及是否允许用户态访问。

每个 xv6 进程有自己的页表。进程切换时，内核也会切换当前使用的页表。一个进程的地址空间通常包含程序代码、已初始化数据、栈和堆。代码页通常不允许写入，数据、栈和堆通常允许读写但不允许执行。

页表还可以把内核需要访问的设备寄存器映射到地址空间中。物理内存分配器负责向内核提供可用的物理页，并在页面释放后将其重新放入空闲链表。

## 第4章 陷阱与系统调用

陷阱是处理器暂停当前执行流、转交给特定处理程序的一类事件。系统调用、设备中断和异常都可以通过陷阱机制进入内核处理。

从用户态发起系统调用时，硬件保存必要的处理器状态并转入内核入口。内核首先保存用户寄存器，然后根据陷阱原因判断是系统调用、设备中断还是错误。处理完成后，内核恢复状态并返回用户程序。

陷阱处理需要同时考虑安全性和正确性。内核不能盲信用户传入的地址和参数，而应当检查参数范围、内存权限和系统调用编号。

## 第5章 页错误

页错误通常表示进程访问了当前没有有效映射或不允许访问的虚拟页面。在 xv6 的教学实现中，页错误可以用于实现延迟分配：程序申请一段地址空间时不立即分配所有物理页，真正访问某个页面时再分配页面并建立映射。

写时复制（COW）是另一种延迟复制思想。父子进程最初可以共享只读页面，只有某一方尝试写入时才触发页错误，内核再复制页面并分别建立可写映射。这样可以减少不必要的复制。

页错误处理必须检查访问是否合法。如果没有可用物理内存，或者访问超出了进程地址空间，内核不能简单地假装成功，而应采取错误处理或终止进程等措施。

## 第6章 中断与设备驱动

设备驱动负责把硬件设备的操作转换成内核可以使用的接口。中断允许设备在需要处理时通知处理器，例如定时器产生时钟中断，串口设备在收到输入时发出中断。

驱动程序通常需要处理并发访问，因为设备中断处理程序和普通内核线程可能同时访问同一组数据。驱动设计需要使用合适的锁或其他同步机制，避免数据竞争。

定时器中断可以帮助操作系统进行时间管理和进程调度。设备驱动还需要处理设备寄存器、缓冲区和错误状态，不能只把硬件看成普通的内存变量。

## 第7章 锁

当多个 CPU 或多个执行流访问共享数据时，可能发生数据竞争。锁用于建立临界区，使同一时刻只有符合条件的执行流修改共享状态。

锁并不能自动解决所有并发问题。内核需要明确锁保护的数据范围、加锁和解锁顺序，以及是否允许在持锁期间睡眠。锁的粒度过大可能降低并发性能，粒度过小又可能增加复杂度。

死锁通常与循环等待有关。例如线程 A 持有锁 1 等待锁 2，而线程 B 持有锁 2 等待锁 1。一个常见的预防方法是为多个锁规定统一的获取顺序，避免形成循环等待。

内存顺序也会影响并发程序。编译器和处理器可能对内存操作进行重排，因此同步原语不仅用于互斥，也用于建立必要的可见性和顺序关系。

## 第8章 调度

多道程序系统需要在多个可运行进程之间分配 CPU。xv6 通过保存和恢复进程的寄存器状态，实现进程之间的切换。

上下文切换包括保存当前执行流的寄存器状态、选择下一个可运行进程、恢复目标进程的状态，然后继续执行。调度器需要处理进程的运行、等待、睡眠和退出等状态。

调度策略会影响公平性、响应时间和吞吐量。一个适合交互式系统的策略可能重视响应速度，而批处理系统可能更重视整体吞吐量。操作系统实现需要在这些目标之间进行权衡。

## 第9章 睡眠与唤醒

当进程暂时不能继续执行时，让它睡眠通常比持续占用 CPU 轮询更有效。条件满足后，其他执行流可以唤醒它。

睡眠和唤醒的实现必须避免丢失唤醒事件。检查条件、释放锁、进入睡眠和重新获得锁之间需要有明确的原子性安排，否则可能出现进程已经睡眠但再也没人唤醒的情况。

管道是进程间通信的一种方式。一个进程写入管道，另一个进程从管道读取。管道可以把多个程序连接起来，并支持流式传输；当管道没有数据或缓冲区已满时，读写进程可能需要等待。

## 第10章 文件系统

xv6 文件系统把磁盘组织成数据块、文件、目录和文件描述符等层次。目录保存名称到文件对象的映射，路径名用于从根目录或当前目录开始定位对象。

inode 表示文件本身的持久化元数据和数据块索引。文件名并不是文件对象本身，同一个 inode 可以通过多个目录项拥有多个名称，这就是硬链接的基础。

缓冲区缓存用于减少对慢速磁盘的重复访问，并协调内核线程对磁盘块的访问。文件系统还需要处理崩溃一致性，避免系统在写入过程中断电后出现元数据和数据不一致。

日志层把一次文件系统操作涉及的修改组织成事务。事务完成后再提交，可以让系统在崩溃恢复时判断一组更新是否应该整体生效。

## 第11章 并发问题再讨论

并发设计不能只关注单个锁，还要关注锁之间的组合关系、数据所有权和不变量。某些场景可以通过无锁算法、消息传递或重新设计数据结构来减少锁竞争，但这些方案通常需要更严格的正确性证明。

并行执行的收益取决于任务是否可以拆分，以及共享数据和同步开销有多大。如果所有线程都频繁访问同一把锁，增加 CPU 数量未必能带来线性加速。

## 第12章 总结

xv6 通过一个规模较小的教学内核展示了操作系统中的核心机制：系统调用、进程、虚拟内存、陷阱、中断、设备驱动、锁、调度、睡眠唤醒和文件系统。

学习 xv6 的重点不是记住每一行代码，而是理解抽象接口、硬件机制、内核数据结构和并发控制之间的关系。回答课程问题时，应先明确讨论的是 xv6 的具体实现，还是适用于现代操作系统的通用概念。
